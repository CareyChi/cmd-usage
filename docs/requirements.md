# 产品需求与验收标准

## A. 产品与运行环境

| 编号 | 需求 | 验收标准 |
| --- | --- | --- |
| A01 | 第三方 CommandCode 用量分析客户端，轻量、迷你，集中展示用量、缓存命中率及账户额度。 | 主界面包含周期标签、汇总、套餐卡片和用量排行；各区域使用一致的数据口径。 |
| A02 | 支持 macOS、Windows 和 Linux 主流发行版，兼容 ARM64、x64。 | macOS 当前及上一主要版本、Windows 11、Ubuntu 24.04 LTS、Debian 13、Fedora 当前稳定版均验证两种架构；覆盖 Linux 的 GNOME、KDE 及 X11、Wayland 支持组合。每个受测组合能启动、登录、显示统计、切换托盘显隐，无阻断性缺陷；记录系统、架构和桌面环境。 |
| A03 | 安装与常驻运行保持轻量。 | 每个平台的发行包 ≤ 80 MiB；安装后应用文件 ≤ 200 MiB。在不少于 4 核、8 GiB 内存、SSD 的设备上，冷启动到可交互 ≤ 3 秒；载入 10,000 条用量记录后，应用进程树常驻内存 ≤ 150 MiB，静置 5 分钟平均 CPU 占用 ≤ 单逻辑核心的 1%；测量不含外部登录页面，网络等待单独计时。 |

## B. 窗口与视觉

| 编号 | 需求 | 验收标准 |
| --- | --- | --- |
| B01 | 小型竖向窗口，用户不可调整尺寸。宽高按当前显示器可用工作区的百分比确定，具体比例根据功能布局在后续界面规划中确定，不使用固定像素作为窗口尺寸基准。 | 窗口高度大于宽度；拖拽边缘、双击标题区及系统最大化操作均不改变规定尺寸。显示器、分辨率或缩放发生变化时自动重新适配。 |
| B02 | 对系统缩放进行反向补偿，保持预期占屏比例，并避开任务栏、Dock、系统面板及屏幕不可用区域。 | 以物理可用工作区为比较基准，同一分辨率在 100%、125%、150%、200% 或系统对应缩放档位下，窗口占宽、占高比例与规划值的偏差分别 ≤ 1 个百分点；内容和窗口均不越界，文字、图标、进度条不重叠或截断。覆盖 1366×768、1920×1080、2560×1440、3840×2160 及不同缩放的多显示器切换；平台不支持的组合注明原因。 |
| B03 | 启动默认位于屏幕右侧，与右边缘保持舒适距离。 | 首次显示在主显示器可用工作区右侧、垂直居中；右侧间距为可用工作区宽度的 2%，误差 ≤ 0.5 个百分点；窗口完整可见。托盘恢复时保留当前位置，显示器移除后重新落在可见工作区内。 |
| B04 | 低调暗色毛玻璃风格，具有科技感；信息层级清晰，卡片分区独立。 | 使用暗色半透明表面、背景模糊及克制的边框或高光；普通文字对比度 ≥ 4.5:1；图例和图形不依赖颜色单独传达含义。平台无法提供背景模糊时使用同色系半透明或实色效果，信息布局与可读性一致。 |

## C. 顶部与托盘交互

| 编号 | 需求 | 验收标准 |
| --- | --- | --- |
| C01 | 左上角显示软件 Logo，单击隐藏到托盘；软件运行期间托盘图标常驻，单击切换显示与隐藏。 | Logo 单击后窗口隐藏、进程保持运行、托盘图标仍在；连续单击托盘图标可依次显示、隐藏窗口，不创建重复窗口或图标。macOS 使用菜单栏状态图标，Linux 在受支持桌面托盘区域显示。 |
| C02 | 显示和隐藏使用简约、短暂的缩放动画。 | 每次动画持续 120–200 毫秒，无闪白或位置跳变；快速重复切换后，最终可见状态与最后一次操作一致，窗口仍可正常交互。 |
| C03 | 右上角提供“日”“周”“月”三个文字标签，单选，默认选择“日”。 | 当前选中项有明确视觉区分；切换同时更新汇总和排行范围；已载入数据的切换在 200 毫秒内完成，两个区域不混用不同周期结果。 |

## D. 周期与统计口径

| 编号 | 需求 | 验收标准 |
| --- | --- | --- |
| D01 | 日、周、月分别表示本日、本周、本月，不是最近 24 小时、7 天或 30 天。按系统当前本地时区统计，周一为一周起点。 | 区间为周期起点（含）至下一周期起点（不含），只统计截至当前时刻已发生的记录。验证午夜、周一、月初、跨年、闰年二月及夏令时切换；边界记录不重复、不遗漏。窗口跨越周期边界后 60 秒内切换为新周期；系统时区改变后同步重算。 |
| D02 | Token 分为未命中输入、缓存输入和输出。总量为三者之和；缓存命中率为缓存输入 ÷（未命中输入 + 缓存输入）× 100%。 | 若原始输入已包含缓存输入，先扣除缓存部分再归类，不能重复相加。汇总命中率用汇总后的数量计算，不能平均各条命中率；例如未命中输入 100、缓存输入 300、输出 50，应得到总量 450、命中率 75.0%。 |
| D03 | 标签下方一行显示所选周期的 Token 总量与缓存命中率。Token 使用 K、M、B，保留两位小数、四舍五入；命中率保留一位小数、四舍五入。 | K = 1,000，M = 1,000,000，B = 1,000,000,000；小于 1,000 时不加单位，仍保留两位小数。先汇总原始数值再格式化；舍入后达到 1,000 时升到下一单位，B 为最大单位。验证 1,234 → 1.23K、13,215,000 → 13.22M、999,995 → 1.00M、94.25% → 94.3%。 |
| D04 | 区分真实零用量与数据不可用。 | 成功读取但没有记录时显示总量 0.00、空列表；输入分母为零时命中率显示“—”。加载中、读取失败、字段缺失分别有简短且明确的状态，不用 0 或虚构数值代替未知数据。 |

## E. 套餐与额度卡片

| 编号 | 需求 | 验收标准 |
| --- | --- | --- |
| E01 | 汇总下方为独立套餐卡片；未登录时显示登录按钮。 | 未登录时按钮可用；登录成功后在同一区域展示对应账户的套餐数据；取消或失败仍可重试，不显示虚构套餐或额度。 |
| E02 | 已登录时，卡片首行显示 CommandCode 套餐名和下次付款日期。 | 套餐名、日期与账户来源一致；日期使用无歧义的年、月、日。无下次付款安排与数据暂不可用分别显示，不推算付款日期。 |
| E03 | 首行下方显示 5h、周限制、月限制的当前已用百分比、进度条及重置日期。 | 三项独立显示；百分比保留一位小数，进度条长度与已用比例相符，误差 ≤ 1 个百分点。超过 100% 时保留真实百分比、条形封顶；重置时间有具体日期与时分，按本地时区展示。账户未提供的限制或重置时间显示“未提供”，不假设为零或无限。 |
| E04 | 额度周期使用账户实际限制周期，独立于右上角的统计范围。 | 切换日、周、月只影响用量汇总和排行，不改变套餐、付款日期及三个额度周期；5h 与周、月重置时间均与账户来源一致。 |

## F. 用量排行卡片

| 编号 | 需求 | 验收标准 |
| --- | --- | --- |
| F01 | 套餐卡片下方为独立排行卡片，数据范围由日、周、月标签决定；按“软件 + 模型”汇总，以总 Token 量降序排列。 | 相同软件和模型合并为一条，不同软件或模型分别展示；原始总量相同则按软件名、模型名升序排列，顺序稳定。完整列表三类 Token 分别求和后与顶部汇总一致。 |
| F02 | 卡片顶部一排显示三个矩形色点，右侧分别标注“未命中输入”“缓存输入”“输出”，颜色依次为绿色、橙色、白色。 | 顺序、颜色和文字固定，与每条信息内的分段条一一对应；滚动列表时图例保持可见。 |
| F03 | 每条信息由三行组成，左侧为对应软件图标，图标占据三行的整体高度；右侧依次为名称、分段细条、数值。 | 名称格式为“CommandCode - deepseek-v4.1-flash”；图标比例不失真，垂直覆盖三行内容区。长名称单行省略，并可悬停查看全文，不挤压其他行。 |
| F04 | 分段细条按未命中输入、缓存输入、输出的占比分为绿色、橙色、白色三段。 | 各段宽度以该条总 Token 为分母；三段总宽度填满条形，误差 ≤ 1 个显示像素，零值不占段宽；总量为零时显示空轨道。比例使用原始值计算，不使用格式化后的数值。 |
| F05 | 第三行均匀设置四个固定列：“输入”“缓存”“输出”“命中率”，各数值紧随自己的标签右侧。“输入”表示未命中输入，“缓存”表示缓存输入。 | 各条记录的四列标签分别横向对齐，数值长度变化不移动标签；四列保持单行，不换行、不重叠、不截断。示例：输入 13.21M、缓存 1.67B、输出 18.60M、命中率 99.2%；数值精度遵循 D03。 |
| F06 | 列表超出卡片可用高度时内部纵向滚动；鼠标进入卡片或焦点位于卡片内时，右侧出现简约竖向滚动条。 | 内容未溢出时不显示滚动条；溢出时能到达首条和末条。鼠标与焦点均离开后隐藏滚动条，显隐不引起内容横向跳动；仅列表滚动，窗口、汇总、套餐和图例保持原位，无水平滚动。 |
